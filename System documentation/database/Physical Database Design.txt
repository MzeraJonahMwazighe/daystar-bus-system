# Physical Database Design

**Version 1.0**

---

# 1. Purpose

The Physical Database Design converts the Logical Database Model into actual database tables that will be implemented in PostgreSQL.

This document defines:

* Table names
* Column names
* Data types
* Primary Keys
* Foreign Keys
* Constraints
* Default values
* Relationships
* Indexing strategy

It acts as the blueprint for implementing the database without ambiguity.

---

# 2. Database Standard

### Database Engine

```
PostgreSQL 17
```

---

### Character Encoding

```
UTF-8
```

Supports

* English
* Student Names
* Emojis (future)
* SMS text

---

### Timezone

```
Africa/Nairobi
UTC +3
```

Never use server timezone.

---

### Naming Convention

### Tables

```

buses

bus_trips

payments

seat_reservations
```

---

### Columns

```
snake_case

payment_status
```

---

### Primary Keys

```
table_id

bus_id

trip_id

ticket_id
```

---

### Foreign Keys

Always named after referenced table.

```
bus_id

trip_id

driver_id

booking_id
```

---

### Dates

```
TIMESTAMP WITH TIME ZONE
```

# 11. Seat Reservation Strategy

This is the most important part.

We are **NOT** storing Seat 1–67 repeatedly.

Instead

```
Bus

↓

Seat Layout

↓

Trip

↓

Reservation
```

Meaning

Seat 20 exists once.

Only reservations change.

This keeps the database small.

---

# 12. Booking Strategy

Student

↓

Trip

↓

Seat Reservation

↓

Booking

↓

Payment

↓

Ticket

---

One booking

↓

Multiple seats

Therefore

Booking and Seats have

```
One-to-Many
```

relationship.

---

# 13. Payment Strategy

Booking created

↓

Seat Reserved

↓

5 minute timer starts

↓

Student Pays

↓

Payment Verified

↓

Booking Confirmed

↓

Ticket Generated

---

If payment fails

↓

Reservation expires

↓

Seats become available
